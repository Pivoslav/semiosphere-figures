Where halt is decided (MA4b, 3D)

When a question can't be answered from licensed sources, the pipeline should say so. MA4b asked where that decision belongs: in the generator's prompt, or in a rule that runs before any model is called. This view follows all 18 frozen items through two of the four arms. In B2 there is no gate, and every item visits the generator twice. In D2 a rule gate reads the retrieved metadata, stops 11 items with the canonical halt string and lets 7 through, so the generator runs 14 times instead of 36.

How to read this

Left to right: the retriever, the rule gate, the generator, and the answer. The green block under the gate is where stopped items land. Pick an arm and press Play. In B2 every particle makes the full trip, including a second loop through the generator for the second hop. In D2 the 11 stopped particles drop into the halt block and never reach the generator at all.

Only the counts are measured. Speed and spacing are there for the eye. The other two arms are on the 2D page: C2 put a halt clause in the prompt and the model refused all 18 items, and E2 combined the gate with a typed halt clause.

Theory tie-in: journal §13 uses this result to argue that the refusal rule belongs upstream, and that once a gate works the prompt clause should go, because in E2 it went on refusing items the gate had already cleared. One caution travels with the 11: on the scoped retriever (MA4c, qwen2.5:3b) the same gate closed 0 of 18, so this figure shows flat retrieval only.
